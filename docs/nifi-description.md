# Apache NiFi 介紹

## Apache NiFi 是什麼？

Apache NiFi 是一套開源的資料流管理工具，用來設計、執行、監控與管理資料在不同系統之間的流動。

它的核心概念是「資料流（Data Flow）」，也就是把資料從來源端接進來，經過轉換、路由、過濾、驗證、格式轉換等處理後，再送到目標系統。

NiFi 提供視覺化操作介面，使用者可以透過拖拉元件建立資料流程，而不一定需要撰寫大量程式碼。每一個處理節點稱為 Processor，例如讀取檔案、呼叫 HTTP API、解析 JSON、寫入資料庫、傳送到 Kafka 等。

## NiFi 解決的問題

在實務系統中，資料通常分散在不同來源，例如檔案、API、資料庫、訊息佇列、IoT 裝置或第三方服務。若每個資料流都自行撰寫程式處理，容易遇到以下問題：

- 資料來源與目標系統很多，整合成本高。
- 資料流程不容易被視覺化追蹤。
- 發生錯誤時，難以知道資料在哪個步驟失敗。
- 需要處理重試、佇列、背壓、流量控制與錯誤路由。
- 需要保留資料流經過哪些處理步驟的紀錄。

NiFi 的目標就是把這些資料流管理能力平台化，讓資料工程師或系統維運人員可以更容易建立與維護資料管線。

## 核心特色

- 視覺化流程設計：透過 Web UI 拖拉 Processor 建立資料流。
- FlowFile 模型：每筆資料在 NiFi 中會被包裝成 FlowFile，包含資料內容與屬性 metadata。
- Processor 元件化：透過不同 Processor 處理讀取、轉換、路由與寫入。
- 背壓控制：當下游系統處理不及時，可以限制佇列大小，避免系統被資料量壓垮。
- Provenance 追蹤：可以追蹤資料從進入到輸出的完整處理歷程。
- 錯誤路由：可以把失敗資料導向不同流程，例如重試、告警或存入錯誤區。
- 即時調整：許多流程可以在 UI 中直接啟停或修改，降低部署成本。

## 常見使用場景

### 1. 系統之間的資料整合

NiFi 常用來把不同系統的資料串接起來，例如：

- 從資料庫讀取資料後寫入另一個資料庫。
- 從 REST API 取得資料後送到資料倉儲。
- 從檔案伺服器讀取 CSV 後轉成 JSON。
- 從舊系統抽取資料後同步到新系統。

這類場景重點是降低系統整合成本，並讓資料流向清楚可追蹤。

### 2. ETL / ELT 資料管線

NiFi 可以作為資料前處理工具，用來完成：

- Extract：從檔案、API、資料庫、Kafka 等來源取得資料。
- Transform：清洗資料、轉換格式、補上欄位、過濾不合法資料。
- Load：寫入資料湖、資料倉儲、搜尋引擎或其他儲存系統。

若轉換邏輯不是非常複雜，NiFi 可以快速建立可視化資料管線。

### 3. 即時資料流處理

NiFi 適合處理持續進來的資料流，例如：

- IoT 裝置資料接收。
- 應用程式 log 收集。
- 使用者行為事件蒐集。
- 即時 API 資料同步。

NiFi 可以負責資料接入、基本清洗、路由與送往 Kafka、資料庫或後續分析平台。

### 4. 檔案交換與格式轉換

在企業系統中，仍常見以檔案作為資料交換方式。NiFi 可用於：

- 監控資料夾是否有新檔案。
- 讀取 FTP / SFTP 檔案。
- 解壓縮或合併檔案。
- CSV、JSON、XML、Avro 等格式轉換。
- 根據檔名、內容或欄位決定資料送往哪個系統。

這類流程若用程式自行實作，通常會重複處理排程、重試與錯誤處理；NiFi 可以把這些能力標準化。

### 5. 資料治理與稽核

NiFi 的 Data Provenance 功能可以記錄資料處理歷程，因此適合需要追蹤資料來源與流向的場景，例如：

- 查詢某筆資料從哪裡來。
- 確認資料經過哪些處理步驟。
- 追蹤失敗資料的位置與原因。
- 支援稽核與問題排查。

這對金融、製造、政府、醫療等重視資料治理的系統特別有用。

## 適合使用 NiFi 的情境

- 需要快速串接多種資料來源與目標系統。
- 希望資料流程可以被視覺化管理。
- 需要處理資料流量控制、錯誤路由與重試。
- 需要追蹤資料處理歷程。
- 團隊希望降低自製資料搬移程式的維護成本。

## 不一定適合使用 NiFi 的情境

- 需要高度複雜的資料運算或機器學習訓練流程。
- 主要需求是大量批次分析，而不是資料流管理。
- 資料轉換邏輯非常客製，且幾乎都必須用程式實作。
- 系統規模很小，只需要簡單的一次性資料搬移。

這些情境可能更適合使用 Spark、Flink、Airflow、dbt、專用 ETL 工具，或直接撰寫程式處理。

## 簡短總結

Apache NiFi 是用來建立與管理資料流的工具。它強項不是取代所有資料處理框架，而是讓資料從多種來源進入系統、經過可控流程處理、再送到正確目的地。

若一個系統需要頻繁整合資料來源、處理檔案交換、接收即時資料、追蹤資料流向，NiFi 會是很適合評估的工具。
